# Agent 的 QQ 原生能力

罐头喵将 NapCat 原生 OneBot 接口接入 Agent，内置 NapCat 4.18.42 的 206 项接口目录。支持消息发送、转发、撤回、表情回应、历史查询，好友管理和申请处理，群管理、公告、文件、相册、待办，账号资料和状态，以及 QQ 空间。接口能否成功取决于当前 NapCat 版本、账号状态和 QQ 自身权限，例如禁言、踢人仍要求机器人具有对应群权限。

无需为每项能力增加独立开关。群 AI 继续由真实主人在目标群 `/ai on` 独立开启，新增能力不会自动开启任何群。

## 调用流程

Agent 使用四个工具，完整接口目录不会一次性发送给模型：

| 工具 | 用途 |
| --- | --- |
| `qq_list_actions` | 中文、接口名或标签关键词搜索；空 query 列出全部，offset/limit 分页 |
| `qq_describe_action` | 列出参数、必填字段和风险；schema_pointer 查询参数的详细 JSON Schema |
| `qq_call_api` | action 指定接口，params 传入原生 JSON 对象；等待最终回执 |
| `qq_read_result` | 使用 result_id 和 pointer/offset/limit 读取已执行操作的结果，避免为翻页再次执行操作 |

例如主人可以说“查一下机器人加入了哪些群”“查看这个群的相册”“把指定消息设为精华”“修改群公告”。Agent 先搜索、查看参数，再根据请求执行。遇到安全审核时，使用已有的带编号审批回复。

原生参数示意：

```json
{
  "action": "get_group_info",
  "params": {"group_id": "YOUR_GROUP_ID"}
}
```

原生参数支持嵌套对象、数组、消息段、布尔值和 null，64 位数字标识符保留精度。参数目录来自静态提取，部分动态类型会退化为宽松描述，实际参数始终由 NapCat 验证。查看复杂消息段时，可用 `schema_pointer: "/properties/message"`，再根据 JSON Schema 的分支继续查询。

## 身份、审批与授权

原生调用入口面向 `bot.master_id` 主人和 `bot.admin_ids` 配置管理员；普通成员继续使用已有的会话工具，不能通过原生入口读取其他群、好友或私聊数据。群内 `/grant`、社区超管和 QQ 群主身份不会自动授予全账号接口权限。

- 已明确列入查询清单的接口直接执行。凭据接口不会因 `get_` 前缀被视为普通查询。
- 发消息、戳一戳、点赞、已读等操作至少为中风险，需要发起人或主人确认。
- 禁言、踢人、群名片、群名称以及其他修改操作至少为高风险，需要主人或配置管理员确认。
- 删除好友、退群、设置群管理员、账号资料、安全设置、原始协议和未知接口等极危能力，仅主人可发起和批准。Cookie、clientkey、rkey、原始协议、快速操作及未知接口还要求在主人私聊执行。
- 原生文件/流式接口以及本机路径只开放给主人；管理员可以使用已有的目录受限文件工具。
- 禁言、单人或批量踢人检查目标，保护主人、配置管理员和机器人自身。

风险下限在 Agent 执行入口判定。`_async`、`_rate_limited` 别名统一为原始接口并同步调用，不能通过别名绕过审批。永久授权记录使用 `qq_call_api/<接口名>`，不会把一个接口的授权扩展到整个 QQ 调用入口；仍受发起人、会话、批准人当前权限及风险等级限制，可用 `/allow list` 查看、`/取消信任 <工具名>` 撤销。审批完成后再次校验发起人权限和群 AI 状态。

以上审核只约束 Agent 工具调用。管理员直接固定命令、私聊管理命令和已配置关键词规则，仍按原有身份和权限执行。

## 回执与较长结果

调用只在 NapCat 最终回执为成功时返回 success。接口错误会保留状态码及错误说明。超时、取消、断线、队列溢出或本地结果保存失败会明确提示执行结果可能不确定，不应自动重试有副作用的操作。

普通结果保存在 `data/qq-results/`（跟随 `data.dir`），返回 result_id 和有长度限制的 JSON 文本片段。`qq_read_result` 仅允许原发起人在原会话读取，读取期限为 24 小时；权限撤销后不能继续读取。pointer 使用 RFC6901，例如 `/messages/0`，offset/limit 为字符偏移和长度。json_fragment 可能只是原始 JSON 的一部分，应按 next_offset 继续读取，不应将片段误判为完整结果。

流式接口持续接收中间帧，将其保存为随机命名的本机 NDJSON 文件，并等待最终完成或失败回执；返回 stream_file、stream_frames 和最终结果。普通 JSON 结果上限 32 MiB，流式接收上限 64 MiB，单次原生调用上限两分钟。流文件包含 Base64 等原始数据，使用已有文件工具在本机处理，不将整条数据流塞入模型上下文。

结果文件属于运行时数据，不提交到仓库。调用接口时最多每小时清理一次超过 24 小时的结果及流文件，避免长期积累。

## 更新目录

应用运行时仅依赖 Go 内嵌目录，不需要 Node。升级 NapCat 后，开发者可静态重新生成目录并重新编译：

```bash
npm install --prefix .local.tools acorn@8.15.0 --no-audit --no-fund
node scripts/extract_napcat_catalog.cjs /path/to/napcat.mjs
go test ./...
go build -o Canmao .
```

生成器解析安装包 AST，不导入或执行 NapCat 应用代码，也不提取接口调用示例中的账号及凭据。未收录接口仍可由主人在私聊通过极危审批尝试，是否支持以 NapCat 回执为准；新增接口不会自动继承查询免审批权限。
